# 首次使用说明与推荐流程

这套系统用于管理完整求职过程：整理个人资料、搜索和筛选岗位、准备申请材料、跟踪申请阶段，以及记录真实投递时使用的准确文件。

建议把它理解为两个协作界面：

- **Web（AI Job Agent）**：管理岗位、申请阶段、当前材料、材料包和投递记录。
- **Codex 对话**：完成联网搜索、岗位分析、材料起草和面试准备等需要 AI 的工作。

Web 不会自动唤起 Codex，也不会替你向公司发送申请。“记录已投递”只是在本地保存已经发生的事实。

## 安装

如果项目还没有安装，复制本仓库的 GitHub 页面地址并在 Codex 中发送：

> 帮我安装并启动 AI Job Agent：`https://github.com/jah0m/ai-job-agent`

也可以按照 [README 中文版](../../README.zh.md#手动安装)中的命令手动安装。

## 0. 启动 AI Job Agent

在 Codex 中直接发送：

> 启动 AI Job Agent

Codex 会使用 `job-search-web` Skill 以非开发模式在后台启动页面，
确认服务健康后打开 `http://127.0.0.1:8765`。如果已在运行，不会
重复启动。

首次安装依赖或需要手动启动时，在仓库根目录执行：

```powershell
python -m pip install -e ".[web]"
Push-Location frontend
npm install
npm run build
Pop-Location
& '.agents\skills\job-search-web\scripts\start_web.ps1'
```

该方式不使用 Vite 开发服务器、preview server 或自动重载。个人资料、
岗位和申请材料只保存在本机 `.job-search/` 目录中。

## 1. 完善个人履历

可以选择下面任意一种方式，也可以混合使用。三种方式最终都会更新 AI Job Agent 中同一份本地个人履历。

### 方式一：在 Web 中手动填写

进入 **个人履历 → 编辑履历**，填写姓名、所在地、联系方式、简介、工作经历、可验证成果、技术技能、语言能力和证书。这种方式适合已经清楚要填写什么，或只需要修改少量内容的情况。

### 方式二：让 Codex 参考现有资料

可以把已有的履歴書、職務経歴書、中文或英文简历、个人经历笔记等文件交给 Codex。例如：

> 参考我提供的这些资料，整理并完善 AI Job Agent 中的个人履历。先提取事实，列出冲突和不确定项让我确认，不要自行补全。

Codex 会先读取当前已经保存的履历，再从资料中提取候选人事实。遇到日期、职位名称、技能水平、成果数字或其他重要信息不一致时，会先询问确认，而不是直接覆盖现有内容。

不要提供与求职无关的敏感文件。需要保留的候选人资料应继续存放在本机私有工作区中。

### 方式三：通过问答逐步完善

如果没有现成简历，可以让 Codex 通过对话引导填写：

> 通过问答帮我完善 AI Job Agent 中的个人履历。一次只问一组相关问题，先完成求职搜索需要的信息，再补充申请材料需要的详细内容。

Codex 会优先询问当前任务真正需要的信息，例如目标岗位、最近的工作经历、主要技能、语言能力和可验证成果；不会要求一次性填写一份很长的表格，也不会重复询问已经保存的内容。

无论使用哪种方式，都只保存能够确认的事实。不确定的内容可以留空或标记为待确认；重要履历信息保存前，Codex 会请你确认。

## 2. 设置求职偏好

进入 **求职偏好 → 编辑偏好**，填写目标职种、地点、远程偏好、最低薪资、不可妥协条件和加分项。条件越明确，后续筛选越有价值。

## 3. 让 Codex 搜索第一批岗位

推荐直接发送：

> 根据我的个人履历和求职偏好，从 TokyoDev、Green、Geekly 和 LAPRAS 搜索一批合适的岗位。先给我匹配度较高的 10 个，不要投递，把结果保存到 AI Job Agent。

如果使用 LinkedIn，请明确地点。不同平台的公开搜索能力不同；遇到登录、验证码或平台限制时，按 Codex 的提示处理。

## 4. 在岗位Kanban完成初筛

进入 **岗位** 页面：

1. 查看职位描述和来源链接；
2. 查看基于履历与偏好的证据型匹配分析；
3. 给岗位评分并记录疑问；
4. 将感兴趣的岗位设为“已收藏”；
5. 明确不考虑的岗位设为“已跳过”。

AI 评估不代表雇主判断，也不能替代查看原始职位页面。履历、偏好或职位信息变化后，可让 Codex 重新分析。

## 5. 为目标岗位创建申请

在岗位详情点击 **创建申请记录**。创建后可在 **申请Kanban** 中管理“准备材料、评估中、准备完成、已投递、面试中、Offer 或已结束”等阶段。

“创建申请记录”不等于已经向公司投递。“已投递”只能通过投递记录进入，不能手动拖入或选择。

## 6. 起草和排版申请材料

在申请详情展开 **让 Codex 协助起草**，复制提示词给 Codex。Codex 会读取候选人资料、职位原文和最新评估，把日文履歴書和職務経歴書写入唯一可编辑的“当前材料”。

推荐流程：

1. 在当前材料中预览或编辑两份 Markdown；
2. 处理所有“要确认”占位符；
3. 需要修改时继续让 Codex 更新同一份当前材料；
4. 下载 Markdown，在 Google Docs、Word 或公司指定模板中排版；
5. 对職務経歴書，也可使用 [Markdown Resume Studio](https://md-resume.jahom.dev/) 做版式预览；
6. 在外部导出实际要投递的 PDF 或 DOCX，再上传到“实际投递文件”。

AI Job Agent 暂不生成 PDF，也不会同步外部工具里的修改。Markdown Resume Studio 的入口目前用于職務経歴書。

## 7. 完成真实投递

投递前确认：

- 个人履历事实已经核对；
- 两份内容没有未处理占位符；
- 招聘平台要求的附件和格式已经确认；
- 已上传并选择本次实际发送的 PDF/DOCX；
- 如果没有附件，选择正确的较低证据等级。

然后在公司招聘网站、邮件或中介渠道中完成真实投递。AI Job Agent 不执行该外部操作。

## 8. 记录已投递

实际投递完成后，回到申请详情填写投递时间、渠道、证据等级和本次实际发送的文件，再点击 **记录已投递**。系统会：

- 将申请阶段更新为“已投递”；
- 分开记录实际投递时间和本地记录时间；
- 从当前材料自动创建不可变材料包并绑定本次投递；
- 对 `exact_files` 只复制本次选中的 PDF/DOCX，并保存哈希；
- 对 `source_only` 或 `status_only` 明确标注证据不足，不假装保存了实际附件。

材料包是证据容器，不是用户必须先完成的流程步骤。通常无需手动创建；被投递记录引用后不可删除。

## 9. 面试和结果跟踪

可以继续让 Codex：

> 根据这个岗位、我的履历和投递记录，准备一份面试问题清单和回答要点。

面试结束后更新申请阶段和备注。Offer、拒绝、撤回或关闭都应保留记录，方便复盘。

## 推荐的日常节奏

- **每周 1–2 次**：让 Codex 搜索并导入新岗位。
- **每天 10–15 分钟**：在岗位Kanban完成初筛。
- **准备投递时**：一次只处理少量高优先级岗位，逐份确认材料。
- **投递当天**：立即记录实际发送文件、渠道和投递状态。
- **面试前**：让 Codex 基于岗位和投递记录准备面试。

## 最短体验路径

1. 填写个人履历；
2. 填写求职偏好；
3. 让 Codex 搜索 10 个匹配岗位，但不要投递；
4. 创建一个申请，让 Codex 起草并保存到当前材料；
5. 外部排版并上传 PDF/DOCX；真实投递后点击“记录已投递”。
