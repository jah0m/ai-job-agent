# はじめての利用ガイドと推奨フロー

[简体中文](first-use-guide.md) | 日本語

このシステムは、転職活動の全体を管理するためのものです。プロフィールの整理、求人の検索と選別、応募書類の準備、応募ステージの追跡、そして実際の提出に使ったファイルの正確な記録までを扱います。

2 つの画面が連携していると考えると分かりやすくなります。

- **Web（AI Job Agent）**：求人、応募ステージ、現在の書類、書類パッケージ、提出記録を管理します。
- **Codex との会話**：Web 検索、求人分析、書類の下書き、面接準備など、AI が必要な作業を行います。

Web から Codex が自動的に起動することはなく、ユーザーに代わって企業へ応募を送信することもありません。「提出済みとして記録」は、すでに起きた事実をローカルに保存するだけの操作です。

> 現在、Web 画面の表示言語は中国語（簡体字）のみです。このガイドでは、画面上の表記をそのまま太字で示し、括弧内に日本語訳を添えています。Codex への依頼は日本語で送信して構いません。

## インストール

まだインストールしていない場合は、このリポジトリの GitHub ページの URL をコピーし、Codex で次のように送信します。

> AI Job Agent をインストールして起動してください：`https://github.com/jah0m/ai-job-agent`

[README 日本語版](../../README.ja.md#手動インストール)のコマンドで手動インストールすることもできます。

## 0. AI Job Agent を起動する

Codex で次のように送信します。

> AI Job Agent を起動して

Codex は `job-search-web` Skill を使い、開発モードではない形でバックグラウンド起動し、サービスが正常であることを確認してから `http://127.0.0.1:8765` を開きます。すでに起動している場合、重複して起動することはありません。

初回の依存関係のインストールや手動起動が必要な場合は、リポジトリのルートで次を実行します。

```powershell
python -m pip install -e ".[web]"
npm ci
npm run build:frontend
& '.agents\skills\job-search-web\scripts\start_web.ps1'
```

この方法では、Vite の開発サーバー、preview server、自動リロードを使用しません。プロフィール、求人、応募書類は、ローカルの `.job-search/` ディレクトリにのみ保存されます。

## 1. プロフィールを完成させる

次のいずれかの方法を選ぶか、組み合わせて使います。どの方法でも、AI Job Agent 内の同じローカルプロフィールが更新されます。

### 方法 1：Web で手入力する

**个人履历 → 编辑履历**（プロフィール → プロフィールを編集）を開き、氏名、居住地、連絡先、自己紹介、職歴、検証可能な実績、技術スキル、語学力、資格を入力します。入力内容がはっきりしている場合や、少しだけ修正したい場合に向いています。

### 方法 2：既存の資料を Codex に参照させる

手元の履歴書、職務経歴書、中国語や英語のレジュメ、経歴のメモなどを Codex に渡します。たとえば次のように依頼します。

> 提供した資料を参考に、AI Job Agent のプロフィールを整理して充実させてください。まず事実を抽出し、矛盾や不確かな点を一覧にして私に確認してください。勝手に補完しないでください。

ここでの目的は候補者の事実を抽出することであり、履歴書を生成したりオンラインで編集したりすることではありません。

Codex はまず保存済みのプロフィールを読み込み、そのうえで資料から候補者の事実を抽出します。日付、役職名、スキルレベル、実績の数値など重要な情報に食い違いがある場合は、既存の内容を上書きせず、先に確認を求めます。

転職活動と関係のない機微なファイルは渡さないでください。保管が必要な候補者資料は、引き続きローカルの非公開ワークスペースに置いてください。

### 方法 3：質問に答えながら少しずつ整える

手元にレジュメがない場合は、Codex に対話形式で進めてもらえます。

> 質問形式で、AI Job Agent のプロフィール作成を手伝ってください。一度に聞くのは関連する質問 1 組だけにして、まず求人検索に必要な情報を埋め、その後で応募書類に必要な詳細を補ってください。

Codex は、希望職種、直近の職歴、主なスキル、語学力、検証可能な実績など、そのときの作業に本当に必要な情報から優先して質問します。長いフォームを一度に埋めさせたり、保存済みの内容を繰り返し尋ねたりはしません。

どの方法でも、保存するのは確認できた事実だけです。不確かな内容は空欄のままにするか、要確認として残せます。重要なプロフィール情報を保存する前に、Codex が確認を求めます。

## 2. 希望条件を設定する

**求职偏好 → 编辑偏好**（希望条件 → 希望条件を編集）を開き、希望職種、勤務地、リモート勤務の希望、最低年収、譲れない条件、歓迎条件、ブラックリスト企業（1 行に 1 社）を入力します。条件が明確なほど、その後の選別が役に立ちます。

## 3. 最初の求人を取り込む

おすすめの方法は 2 つあります。

### 方法 1：求人 URL を直接貼り付ける

求人サイトで気になる求人をすでに見つけている場合は、公開されている求人詳細ページを Codex に送ります。

> この求人を AI Job Agent に取り込んでください：`<求人詳細ページの URL>`

Codex は求人詳細の全文を読み、確認できる情報を整理して、求人を「**新发现**（新着）」として保存します。知人から共有された求人、企業の採用ページ、ほかの経路で見つけた求人に向いています。

URL は公開アクセスできる必要があります。ログインページ、応募フォーム、紹介リンク、CAPTCHA が必要なページは、求人詳細として取り込めません。

### 方法 2：Codex に検索してもらう

まだ目標がはっきりしていない場合は、次のように送信します。

> 私のプロフィールと希望条件をもとに、TokyoDev、Green、Geekly、LAPRAS から合いそうな求人を検索してください。まずマッチ度の高い 10 件を挙げ、結果を AI Job Agent に保存してください。

LinkedIn を使う場合は、勤務地を明示してください。公開検索でできることはサイトごとに異なります。ログイン、CAPTCHA、サイト側の制限に当たった場合は、Codex の案内に従って対応します。

### Codex による求人情報の整理

求人を保存するとき、Codex はまず求人詳細の全文を読み、閲覧や選別がしやすい形に整理します。提供される内容は求人サイトによって異なります。ページに明記されていない情報は空欄のままとし、推測したり繰り返し質問したりはしません。

勤務地は `東京都赤坂` のようなエリア名に簡略化されます。詳細な住所、リモート勤務の条件、週あたりの出社要件はそれぞれ別に保持され、勤務地の欄にまとめて詰め込まれることはありません。年収も、求人ページに明確な根拠がある場合にのみ表示されます。

## 4. 求人 Kanban で一次選別を行う

**岗位**（求人）ページを開きます。

1. 求人内容と掲載元のリンクを確認する。
2. プロフィールと希望条件にもとづく、根拠付きのマッチ度分析を確認する。
3. 求人を評価し、疑問点を記録する。
4. 興味のある求人を「**已收藏**（保存済み）」にする。
5. 検討しないと決めた求人を「**已跳过**（見送り）」にする。

AI の評価は企業側の判断を表すものではなく、元の求人ページの確認に代わるものでもありません。プロフィール、希望条件、求人情報が変わったら、Codex に再分析を依頼できます。

## 5. 目標の求人について応募を作成する

求人詳細で **创建申请记录**（応募記録を作成）をクリックします。作成後は **申请Kanban**（応募 Kanban）で、「准备材料（書類準備）、评估中（評価中）、准备完成（準備完了）、已投递（提出済み）、面试中（面接中）、Offer（内定）、已结束（終了）」の各ステージを管理できます。

「応募記録を作成」は、企業への提出が済んだことを意味しません。「提出済み」には提出記録を通じてのみ移行でき、手動でドラッグしたり選択したりすることはできません。

応募詳細の **下一步行动**（次のアクション）で、具体的な ToDo を 1 つと、任意の期限を設定します。サイドバーの **今日待办**（今日の ToDo）ページには、ローカルの日付にもとづいて、期限切れ、今日が期限、今後が期限、期限なしのアクションが表示されます。期限を変更して保存すれば延期できます。完了後は、再開したり次の項目を設定したりできます。終了した応募は ToDo ページに表示されませんが、履歴は応募内に残ります。

ToDo はローカルワークスペースに保存され、再読み込みや再起動の後も確認できます。ToDo を完了しても応募ステージは変わらず、通知やメールの送信、アクションの自動実行も行われません。複数のページで同じ ToDo を編集した場合、古いページには再読み込みを促す表示が出て、新しい内容の上書きを防ぎます。

ToDo 機能を含むバージョンにアップグレードした後は、Web サービスを再起動すると保存用のテーブルが自動的に追加されます。CLI のみを使う場合は、先に `python scripts/job_search.py init` を実行します（既存データは保持されます）。`application show` は `next_action` を返します。`application action <応募ID> --title "次のアクション" --due-date YYYY-MM-DD --expected-revision <ToDoのrevision>` で保存でき、`--operation complete` / `reopen` / `clear` で更新できます。ToDo の revision は、書類のバージョンとは独立しています。

## 6. 応募書類の下書きとレイアウト

応募詳細で **复制起草指令**（下書き指示をコピー）をクリックし、引き継ぎの説明に従って指示を Codex に貼り付けて送信します。指示をコピーしても AI のタスクは開始されません。Codex は候補者資料、求人票の原文、最新の評価を読み込み、求人ごとの日本語の職務経歴書を、唯一編集可能な「現在の書類」に書き込みます。タスクが完了して保存されたら、Web に戻って **刷新查看结果**（更新して結果を確認）をクリックし、内容を確認します。クリップボードが使えない場合は、説明を展開して指示を手動でコピーできます。求人の検索、分析、プロフィールの整備でも、同じ引き継ぎの流れを使います。

書類準備の進捗は 3 項目に分かれています。職務経歴書の基本チェックの通過、最終版 PDF/DOCX のアップロード、確認後の現行バージョンの書類パッケージの保存です。ファイルが存在するだけではチェック通過にはならず、過去の書類パッケージがあっても、修正後の現在の書類が確認済みであることにはなりません。チェックは、本人によるファイル内容の確認に代わるものではありません。外部への提出記録は別に表示され、書類準備の進捗には含まれません。

自分で管理している定型の履歴書がある場合は、**上传实际投递文件**（実際に提出するファイルをアップロード）のステップで **履歴書（用户自备）**（履歴書・ユーザー持参）を選び、PDF/DOCX をアップロードできます。システムはこれをユーザー提供の書類として書類パッケージと提出記録に保持し、履歴書を生成したりオンラインで編集したりはしません。

推奨フロー：

1. 現在の書類で、職務経歴書の Markdown をプレビューまたは編集する。
2. 「要確認」のプレースホルダーをすべて解消する。
3. 修正が必要な場合は、引き続き Codex に同じ現在の書類を更新してもらう。
4. Markdown をダウンロードし、Google Docs、Word、または企業指定のテンプレートでレイアウトする。
5. 職務経歴書については、[Markdown Resume Studio](https://md-resume.jahom.dev/) でレイアウトをプレビューすることもできる。
6. 実際に提出する PDF または DOCX を外部で書き出し、「実際に提出するファイル」にアップロードする。

AI Job Agent は現時点で PDF を生成せず、外部ツールでの修正も同期しません。Markdown Resume Studio への入口は、現在のところ職務経歴書用です。

## 7. 実際に提出する

提出前に次を確認します。

- プロフィールの事実を確認済みである。
- 職務経歴書に未処理のプレースホルダーが残っていない。
- 求人サイトが求める添付ファイルと形式を確認済みである。
- 今回実際に送信する PDF/DOCX をアップロードし、選択している。
- 添付ファイルがない場合は、該当する低い証拠レベルを選んでいる。

そのうえで、企業の採用サイト、メール、または転職エージェント経由で実際に提出します。AI Job Agent はこの外部操作を行いません。

## 8. 提出済みとして記録する

実際の提出が終わったら、応募詳細に戻り、提出日時、経路、証拠レベル、今回実際に送信したファイルを入力して、**记录已投递**（提出済みとして記録）をクリックします。システムは次の処理を行います。

- 応募ステージを「提出済み」に更新する。
- 実際の提出日時とローカルでの記録日時を分けて記録する。
- 現在の書類から変更不可の書類パッケージを自動作成し、今回の提出に紐付ける。
- `exact_files` の場合は、今回選択した PDF/DOCX のみをコピーし、ハッシュを保存する。
- `source_only` または `status_only` の場合は、証拠が不十分であることを明示し、実際の添付ファイルを保存したかのようには扱わない。

書類パッケージは、準備段階で確認して保存することも、実際の提出後に記録する際に自動作成することもできます。準備の進捗は、すでに行われた提出を記録するための必須条件ではありません。低い証拠レベルでも、事実のとおりに記録されます。提出記録から参照されている書類パッケージは削除できません。

## 9. 面接と結果の追跡

引き続き Codex に依頼できます。

> この求人、私のプロフィール、提出記録をもとに、面接の想定質問リストと回答の要点を準備してください。

面接後は、応募ステージとメモを更新します。内定、不採用、辞退、クローズのいずれも、振り返りのために記録を残しておきます。

## おすすめの日々のペース

- **週 1〜2 回**：Codex に新しい求人を検索して取り込んでもらう。
- **毎日 10〜15 分**：求人 Kanban で一次選別を行う。
- **提出の準備時**：一度に扱うのは優先度の高い少数の求人に絞り、書類を 1 件ずつ確認する。
- **提出当日**：実際に送信したファイル、経路、提出状況をすぐに記録する。
- **面接前**：求人と提出記録をもとに、Codex に面接準備をしてもらう。

## 最短の体験ルート

1. プロフィールを入力する。
2. 希望条件を入力する。
3. Codex にマッチする求人を 10 件検索して保存してもらう。
4. 応募を 1 件作成し、Codex に下書きを作成して現在の書類に保存してもらう。
5. 外部でレイアウトして PDF/DOCX をアップロードし、実際の提出後に「提出済みとして記録」をクリックする。
